# PLEA design system

## Overview

PLEA is a public Sepolia court for holders buying a token, making a case to sell, and following verdicts and season prizes. The interface takes the character of a private court: ink, parchment and wax red, with generous space and restrained typography. The identity is the word **PLEA**, set tightly in Instrument Serif; it has no logo icon or badge.

The implementation lives in `web/src/style.css`, shared components in `components.tsx`, the persistent shell in `App.tsx`, and page compositions in `pages.tsx`, `Plead.tsx` and `Trade.tsx`. The Overview pairs a short introduction with immediate actions. Other pages begin with a title and one explanatory sentence, then their task. Live numbers support those tasks rather than forming oversized heroes.

## Typography

`main.tsx` imports self-hosted WOFF2 assets through `@fontsource/instrument-serif` (Latin regular and italic 400) and `@fontsource-variable/geist` (variable weight files with language subsets). Vite emits the font files into `dist/assets/`; there are no font CDN requests. Browser inspection confirmed both loaded. The favicon outlines an Instrument Serif P, so it does not depend on a system font. Display text uses `"Instrument Serif", serif`; body and controls use `"Geist Variable", sans-serif`. The generic families are fallbacks only. Monospace is confined to full addresses. Tabular numerals are enabled globally with `font-variant-numeric: tabular-nums`.

| Token | Size | Use |
|---|---|---|
| `--text-small` | 14px / .875rem | metadata, hints, table text |
| `--text-body` | 16px / 1rem | body and controls |
| `--text-lead` | 18px / 1.125rem | introduction, subsection headings |
| `--text-title` | 24px / 1.5rem | plea text and medium emphasis |
| `--text-heading` | 32px / 2rem | section headings, detail plea text |
| `--text-display` | 56px / 3.5rem; 48px at ≤700px | page titles and wordmark |

Body line-height is 1.6. H1/H2 use 400 weight and 1.12 line-height, with tracking −.025em / −.01em. H3 uses Geist 600 and 1.4 line-height. Buttons use 500. The wordmark uses −.055em tracking and line-height 1. Paragraphs stop at 70ch, headings use balanced wrapping, and plea text respects its original direction with `dir="auto"`.

The on-chain Laureate SVG retains its contract-authored typography and artwork. It is displayed as an image, not restyled or regenerated by the website.

## Layout

One spacing scale supplies `--s1` through `--s9`: 4, 8, 12, 16, 24, 32, 48, 64 and 96px in rem units. Header, main and footer share a maximum width of 1200px, with 32px outer margins on larger screens and 16px at ≤700px.

`intro-grid`, `two-column` and `detail-layout` use twelve equal columns with 48px gaps (32px on mobile). The main task takes the broader area and supporting information sits beside it. The Overview's four live figures form a simple definition list. No content panel is nested inside another card.

| Width | Implemented behavior |
|---|---|
| Above 1050px | Wall has three columns; Laureate gallery has three columns; seven navigation items share one row. |
| 701–1050px | Wall and gallery have two columns; introductory/supporting column spans adapt. |
| 701–900px | Form and plea-detail layouts become one column, keeping fields readable. |
| ≤700px | All primary grids become a true single column; Wall/gallery one column; live strip two columns; addresses one column; footer stacks; navigation becomes four items then three, all visible. |

Tables stay within the viewport with fixed layout, wrapping wallet labels and compact cell padding. Long addresses wrap anywhere. At 360px all navigation items remain visible; no horizontal-scroll tab strip is used. Seven routes also passed a 320px reflow check. Product and Buy PLEA were visible above 462px in the 390×844 first-screen check. The full 360/768/1280 matrix was rendered in both themes.

## Elevation & Depth

The surface system is flat: a tinted page, subtly lighter/darker cards and fields, and 1px boundaries. There are no shadows, offset layers, gradients, glass, blur or glow. The skip link is the only fixed element, with `z-index: 10` so it can appear above the header when focused. No dialog or modal layer exists.

## Shapes

Controls and notices use a small 3px corner radius; plea cards are square and use a single 1px border with consistent 24px padding. The season link is a pill. The verdict seal has an irregular rounded outline (`44% 49% 45% 48%`) with a circular inset 1px ring, a −9° rotation, display-face text and wax colors. The `gold` variant reuses the same seal for Laureates. Tiny state dots supplement explicit alive/dead text.

## Components

- **Shell (`App.tsx`)**: wordmark, Cabal clock, current season/pot link, theme toggle and one Connect control. The seven-item navigation marks the active route with text and an underline. After Cabal death, Sell replaces Plead and links to the sale form. Hash navigation updates the title, scrolls to the top and focuses `main` without hiding the header. A keyboard skip link also focuses `main`.
- **`TxButton` (`components.tsx`)**: names the action and accepts `primary`, `disabled` and an action callback. Local feedback distinguishes preparation, wallet confirmation, pending and confirmed states. Confirmation links to the explorer. Errors name the problem and recovery. Buttons are disabled without the required live state/wallet or while another write is in progress. `WalletHint` explains the top-bar connection requirement without adding another Connect button.
- **Buttons and links (`style.css`)**: `.button.primary` uses the accent; secondary buttons are outlined; `.text-link` and `.text-button` are underlined. Targets are at least 44px. Hover changes fill or underline, keyboard focus uses a 2px outline with 4px offset, disabled controls retain readable tinted contrast, and `aria-busy` announces loading. `External` adds only a regular Phosphor arrow with an accessible text label.
- **`FaucetButton` (`components.tsx`)**: reads TestIMD allowance and cooldown from chain, shows the connected wallet’s countdown and disables requests until it ends.
- **Fields (`Plead.tsx`, `Trade.tsx`, `pages.tsx`)**: visible native labels, helper/error associations, decimal input modes, native textarea resizing, live UTF-8 byte count, live name availability and fact score. Error copy is adjacent to the relevant control. A quote shows spent/received amounts before any trade action becomes available.
- **`PleaCard` / `PleaGrid` (`components.tsx`)**: flat bordered records containing author, text, verdict, amount, scores, season points, state, timestamp and links. Appeal relationships have written Denied → Overturned/Upheld links. State labels remain visible independently of seal color. `detail` enlarges the text on a permalink page; cards never render user-provided HTML.
- **`Stamp` (`components.tsx`)**: `label`, `gold` and `animate` are the actual props. When an existing pending card receives a verdict, `.stamp-arrives` uses the only authored animation: 550ms, `cubic-bezier(.16, 1, .3, 1)`, scale 1.35→1, rotation −16°→−9°, opacity 0→1. The entire animation exists only under `prefers-reduced-motion: no-preference`. No other animation or transition is used.
- **`Notice` / `Empty`**: plain-language status/error information, a useful next action when applicable, and semantic status/alert roles. Loading reads show explanatory text without animated skeletons. An unavailable RPC preserves the previous figures with a stale-data message and disables writes.
- **`Leaderboard` (`pages.tsx`)**: semantic table with caption, scoped headers, ten ranks, qualification explanation, prize shares and actual/projected amounts. The connected wallet's row gets a tinted fill. Hall of Fame uses native disclosure elements with actual payouts from events.
- **`NFTGallery` and `OracleDetails` (`components.tsx`)**: live on-chain artwork with descriptive alt text and gold seals; judge reasons in a native expandable record with source links. Oracle content failures have a retry action and leave contract state usable.

All icons come from Phosphor with regular weight. Icons appear for theme choice, external navigation, refresh and transaction state; they do not replace button labels or form labels.

## Do's and Don'ts

Start a new route with the existing shell, `page-heading` and an appropriate grid. Reuse semantic tokens, one of the six text sizes, and the spacing scale. Use `TxButton` for every write so gas, network, receipt and error behavior remain consistent. Choose one primary action for a task; use secondary/text controls for alternatives. Show units next to values and number seasons as `key + 1`.

Keep the wordmark typographic, cards flat, verdict motion unique, and controls at least 44px. Do not introduce another font, icon library, independent spacing scale, nested cards, decorative badges, clipped navigation, large-number heroes or modal workflows. Never use color as the only state signal. New on-chain values should join the live reader rather than become fixed marketing numbers.
